# 1.7.0

_Released 2026-05-06._

## Features
- Export now resolves all library placeholders inside `CMakePresets.json`. The profiling presets (`x64-Debug-Profile`, `x64-Release-Profile`) ship with the correct `<LIB_SHORT>_PROFILING` cache variable instead of the literal template token, so newly created libraries support profile builds without manual edits.
- Upgrade now preserves developer-added macro definitions in `CMakePresets.json` and `CMakeSettings.json`. Custom `cacheVariables` keys (presets), custom `-D…` tokens in `cmakeCommandArgs`, and custom `variables[]` entries (settings) survive a template refresh. Template-managed values still take precedence on conflicting keys; quoted values like `-DPATH="C:/Some Dir"` round-trip intact.
- Unittest discovery: `unittests/<folder>` now matches its executable in `build/Release/` via a fuzzy algorithm (exact → normalized token equality with `_-.` stripped and trailing `test/unittest(s)` chopped → bidirectional substring, tie-broken by length delta). Folders without a match are surfaced in the result dialog as failed suites instead of being silently dropped.
- Unittest result dialog: per-suite sub-rows under each repository row show individual pass/fail/cancel status with their own "Show log" buttons; the card's "Show log" still opens the combined log.
- Repository card: **Terminate** button per card (uses `terminate.png`); ribbon **Terminate all** button in the Repositories → Build group stops every in-flight parallel build, unittest, and cancels the queue in one shot.
- Log viewer overhaul (`TextLogWindow`): toolbar with Find (Ctrl+F), Save-as (Ctrl+S), Copy all, Wrap toggle, Highlight toggle, Next-issue jump, Top / End; find bar with case / whole-word / regex options and live match count; line-number gutter; syntax highlighting for PASS/OK/SUCCESS (green), FAIL/FAILED (red), ERROR/FATAL/CRASH (red-on-tint), WARN/DEPRECATED (orange), INFO/DEBUG (blue), SKIP/IGNORED (purple), `===== <suite> =====` separators (cyan), MSBuild `N error(s)` / `error C1234:` patterns, and a full-line callout for `Testresult: PASS/FAIL`.
- Push / Pull / Commit / Discard buttons now static-disable per repo based on capability: no git repo → Commit/Discard/Pull/Push all disabled; git repo without a configured remote → Pull/Push disabled. Tooltips explain the reason. Group actions from the ribbon filter checked repos by the same rules and show a skipped-repositories dialog.
- Repository cards: Discard uses `reset.png`, Clean uses `clean.png`; ribbon group buttons match.

## Changes
- App data location moved from the per-user `%APPDATA%\KROIA\CmakeLibCreator` (Qt `AppDataLocation`) to the machine-wide `C:\ProgramData\KROIA\CmakeLibCreator` (Qt `GenericDataLocation` + org/app). On first launch under the new location, `settings.json` and the cached `data/{template,dependencies,qtModules,stylesheet}` folders are copied over from the old location; the old path is left untouched and can be deleted manually.
- `UnitTestRunner::finished` signal now carries a `QVector<UnitTestSuiteResult>` (per-suite name, exe, code, log). `RepositoryInfo` gained `unitTestSuites`. New `UnitTestSuiteResult` metatype is registered for queued cross-thread delivery.
- `JobResultDialog::showLogRequested` now takes an additional `subKey` parameter — empty for the combined repo log, set to a suite name for per-suite logs.
- `BuildRunner::cancel(repoPath)` added for single-repo termination alongside the existing `cancelAll()`; per-repo cancel flag is consumed by `runBuildProcess` to distinguish `ResultCanceled` from `ResultFailed`.
- `UnitTestRunner` tracks the current suite's pid; new `cancel(repoPath)` and `cancelAll()` taskkill the running exe and mark the run as canceled.
- `RepositoryInfo` gained `hasRemote`, populated by `RepositoryJobQueue::refreshStatus` via new `Utilities::gitHasRemote()`.

## Bugfixes
- Doxygen `// @file LibraryName*.h` comments at the top of every generated header are now substituted with the project's actual library name on export.
- USER_SECTION marker detection no longer trips on prose comments that merely mention the keyword. The parser now requires strict syntax — the line, after trimming, must begin with the doubled comment prefix (`##` for cmake, `///` for code) followed by `USER_SECTION_START <N>` or `USER_SECTION_END`. Single-`#` cmake comments (or `//` C++ comments) that contain `USER_SECTION_START` as text are correctly ignored.

## Deprecations
- Removed `CMakeSettings.json` handling. The file has been dropped from the QT_cmake_library_template (template version 1.7.0); CMakePresets.json — the portable, IDE-agnostic equivalent — is now the only build-config file the tool manages. Existing user projects keep their `CMakeSettings.json` untouched on upgrade; the tool simply ignores it.
