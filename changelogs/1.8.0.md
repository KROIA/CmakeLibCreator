# 1.8.0

_In development. Entries below are populated as tasks complete; final list compiled at release._

## Features
- Settings and the downloaded `data/` tree (templates, dependencies, Qt modules, stylesheet, scratch) now live in the per-application AppData folder (`%AppData%\Roaming\KROIA\CmakeLibCreator\` on Windows). Wiping the build folder no longer destroys settings.
- New **Project Paths** editor inside the existing Settings dialog: add, remove, and browse for the project paths previously only editable by hand-editing `settings.json`.
- New **Default library path** setting (Settings dialog). Browse buttons inside the editor and the "Open existing library" / "Save as new" file dialogs all default to this path when no project is loaded yet. Default value: `<Documents>\Visual Studio 2022\Projects`.
- New **Repositories** ribbon tab and central page: one card per managed repository showing uncommitted-changes flag, HEAD commit subject, library version, template version, build status and unittest status (with a "Show log" window for the last test run).
- Per-repository action buttons on each card: Open folder, Update template, Pull, Push, Commit, Discard, Build, Clean, Unittest. Individual actions always run regardless of the group checkbox.
- **Group operations** over a checkbox-selected subset of repositories, run strictly sequentially through a cancelable job queue. Group buttons: Open folders, Update templates, Refresh status, Pull, Push, Commit, Discard, Build, Clean, Unittest.
- The group selection checkbox per repository is **persisted** in `settings.json` and restored across restarts.
- **Status bar** now shows job progress ("Verb n/m: repo" + progress bar) with a **Cancel** button that immediately kills the running process tree and drops the remaining queue.
- **Warning flows**: dirty-repo warning before template update, failed-build/unittest warning before commit, discard confirmation, and a single group summary dialog (Proceed for all / Skip affected / Cancel) for group pre-checks.
- Ribbon tab and central page stay in sync (index 0 = Project editor, index 1 = Repositories).
- Each threaded card button now shows a small status label beneath it (working / ok / fail / cancel, auto-clearing) and turns blue with a "what's running" tooltip while its task runs; re-clicking a running button is a no-op.
- Unittests now run **in parallel**, off the sequential queue (one worker thread per repository), so testing one library no longer blocks building or testing another. A repository's unittest is refused while that same repository is building, and unittests run even against externally-built binaries as long as `build/Release/*.exe` exist (missing → error popup).
- **Build results** and **Unittest results** popups: after a run, a window lists each repository with its result and a "Show log" button (opens the shared log viewer). Group runs accumulate all repositories into one popup, updating live and reopening if closed; a new run resets the list.
- Buttons with descriptive tooltips throughout the Repositories tab.
- Update template now **skips repositories already on the current template version** (info popup instead of a pointless rewrite).
- Committing a repository with no changes, or pushing one with nothing to push, is now ignored with an info popup.
- **Clean** now asks for confirmation before deleting the build folder.
- Builds now run **in parallel** across repositories, capped by a new **Max parallel build threads** setting (default 4). More than one build script runs at once, up to the cap; extra builds wait for a free slot.
- Repository actions are no longer globally disabled while work runs. Only actions on the *same* repository that would collide with an in-progress operation are disabled; every other repository stays fully usable.

- First automated test suite for the tool itself: `unittests/ExportRenameTest`, built when `COMPILE_UNITTESTS` is `ON` (now the default). `TST_exportRename` creates a library in a temp folder, seeds a marker inside a `USER_SECTION`, re-exports it under a new name and asserts the marker survived into the renamed file, that no trace of the old name remains, and that the profiling token agrees across `CMakeLists.txt`, `CMakePresets.json` and the generated debug header. `TST_profileDefine` drives the real settings dialog through the KROIA UnitTest GUI module. Both skip rather than fail when their prerequisite (a downloaded template, a GUI session) is missing, and the temp tree is removed even when an assertion fails. `TST_exportRename` also **compiles the generated library on both sides of the rename**: the first build leaves a configured CMake cache carrying the old file names, and the second has to survive it. That second build is required to reconfigure rather than recompile — the template globs its sources, CMake caches glob results at configure time, and a stale cache would build a file list that no longer exists. The suite proves the glob was re-evaluated by asserting the build output names the new file and not the old one. Whole suite: ~18 s, ~600 MB of temp tree, cleaned up.

## Bugfixes
- Fixed re-exporting an existing project under a **new library name** leaving the whole previous generation of files behind. The old `<OldName>_*.h/.cpp/.h.in` files and any folder carrying the old name are now renamed before anything is copied, so the project no longer ends up with two complete copies of the library infrastructure compiled into one target (missing `_meta.h`, and stale sources defining symbols declared `__declspec(dllimport)`).
- Fixed a **silent loss of `USER_SECTION` code** on rename. User sections are keyed by absolute file path; because the previous generation was never renamed, the sections were re-applied to the stale files and the newly generated ones shipped empty. The stored section keys are now migrated together with the files on disk. A section key that cannot be migrated, or that points at a missing file afterwards, is logged as an error instead of passing silently.
- Fixed dead `<OldShort>_PROFILING` cache variables accumulating in `CMakePresets.json` on every re-export. The placeholder replacement now works from the values the project currently uses, not from the pristine template tokens, so the old entry is rewritten instead of a new one being appended alongside it.
- Fixed the `-Profile` presets building successfully with **easy_profiler silently disabled**. `LIB_PROFILE_DEFINE` was derived from the capital letters of the library name while `CMakePresets.json` and the generated `<name>_debug.h` used the short define, so the build system passed one token and the headers guarded on another whenever the two disagreed (e.g. library `DTI801_Driver` with short define `DTI801` produced `DTID_PROFILING` against `DTI801_PROFILING`). The profile define is now derived from the short define, and follows it when the short define is edited by hand.
- Fixed a rename leaving the **old namespace** behind in `examples/` and `unittests/`, so the renamed project did not compile (`OldName::Profiler::start()` against a namespace that no longer exists). Qualified uses matched none of the existing replacement filters. Namespace references are now rewritten on any line containing `::` or `namespace`, **including inside `USER_SECTION` blocks** — a rename that leaves your own code pointing at a namespace that no longer exists is worse than the tool touching it.
- Fixed three Qt fields being left **uninitialised** by `CMAKE_settings`' constructor — `qt_versionNr[3]`, `qt_useNewestVersion` and `qt_autoFindCompiler` held whatever was on the stack. Harmless through the GUI, where the settings dialog writes all three before anything reads them, but `getValidated()` reads them via `getQtVersionStr()`, so any code path that exported without going through the dialog could emit a garbage `QT_MAJOR_VERSION`. All Qt fields now start at the same defaults the template itself uses: install base `C:/Qt`, Qt 5, auto-find version, auto-find compiler. (An empty Qt module list on a fresh project is unchanged — that is deliberate and matches what the dialog presents.)
- Removed `replaceTemplateFileNames()`, which had been dead since the template copy started renaming files inline — it searched for the pristine `LibraryName` token that no longer exists on disk by the time it ran.
- Fixed the Repositories job queue running its worker on the GUI thread (a `QThread::started` connection bound to a GUI-affinity context object): builds froze the UI and a second queued build never started. Repository jobs now run on the worker thread; the UI stays responsive and the console shows build output live.
- Fixed the build "Show log" opening an empty view: the post-build status refresh was clobbering the captured build log.
- Fixed a crash on application close (access violation in the ribbon/central tab-sync during teardown).
- Project-path list no longer reverses its order on every settings save (old `push_front` bug).
- Removed the broken git status checks (`gitHasUncommitedChanges` counted unpushed commits with invalid bash `$()` syntax; `gitHasUnpushedCommits` hardcoded `origin/master`; `gitBehindRemote` was never called). Replaced by `gitIsDirty` using `git status --porcelain`.
- Build invocation now runs via `QProcess` working directory instead of an unquoted `cd`, fixing repository paths that contain spaces.
